# 项目介绍话术（可直接背）

> 使用说明：
> 1. 方括号 `[ ]` 里的内容**必须换成你自己的真实数据**，不要照抄也不要编
> 2. 背的是**结构和顺序**，不是逐字——背太熟会像机器人
> 3. 每段后面都留了"可能追问"，那是面试官最容易接话的地方，提前想好

---

## 一、1 分钟版本（最常用）

**触发场景**：面试官说"介绍一下你自己" 或 "说说你最近做的项目"

```
我最近做的是[华为钱包]的卡券服务测试，属于金融级的业务。

简单说，卡券就是虚拟资产——商户创建卡券模板，发给用户生成实例，
用户核销的时候要保证商户侧和用户侧的状态一致，这个和账务的逻辑是一回事。

技术上它是一条双向链路：商户服务器调华为创建卡券，
卡券状态变化之后华为会回调商户的接口。
所以除了正向接口，回调的幂等和失败补偿也是我在测的重点。
安全方面走 OAuth 取 token，报文做 JWE 签名。
测试环境分中国、亚洲、欧洲、拉美、俄罗斯五个区域，各有一套域名。

我的日常是写用例、执行、抓日志定位问题。
平台用的是华为的 CloudTest，通用能力平台已经封装好了，
业务场景的编排和异常定位是我来做。
```

**这段话覆盖了银行和金融类岗位最关心的四件事**：
一致性（虚拟资产）、异步回调（双向链路）、安全（OAuth + JWE）、环境管理（多区域）

### 可能追问

| 追问 | 准备方向 |
|---|---|
| "举个例子说说你发现的问题" | **必须准备一个真实案例**，见第三节 |
| "CloudTest 是什么？" | "华为自研的云测平台，类似 Postman 但能做平台化用例管理和持续集成" |
| "回调怎么测的？" | "验证重复回调的幂等、回调失败的补偿、签名校验失败是否拒绝" |
| "JWE 签名具体怎么做的？" | "RSA 私钥签名，华为侧验签；我会构造签名错误的报文验证服务端确实拒绝" |

## 二、3 分钟版本（技术深挖时用）

**触发场景**：面试官开始追技术细节，"你这个框架怎么搭的"

```
我自学搭了一套 Python 接口自动化框架，用来练手和理解框架设计。

最初是直接在脚本里写请求，写完发现几个问题：
地址写死了、token 每个用例都要手动加、没有日志不知道失败时请求了什么、
加一条用例要复制粘贴改一遍。

所以做了分层，分五层：
第一层是配置层，环境地址、超时放在 YAML 里，换环境只改一个文件；
第二层是公共层，日志、YAML 读写、变量池这些工具；
第三层是请求封装，所有请求都走这一层，统一做变量替换、拼 URL、设超时、记日志、捕异常；
第四层是业务层，每个模块一个类，继承一个父类，只写接口路径和业务参数；
第五层是用例数据层，用例写在 YAML 里，包含请求、提取、断言三部分。

最核心的是用例执行引擎：它读一条 YAML，替换变量、发请求、
从响应里提取字段存进变量池、再按规则断言。
正因为有这个引擎，加一条用例只要往 YAML 里加一段，不用写 Python 代码。

接口依赖用变量池解决：上游用例提取出来的字段存进全局字典，
下游用例用 ${变量名} 占位，发请求前统一替换。
这里踩过一个坑——替换的时候如果一律转成字符串，
整数类型的 userId 会变成 "5"，服务端就匹配不上了，
后来改成整串是占位符时保留原类型。

数据清理用 pytest 的 fixture，yield 之前造数据，yield 之后删掉，
就算用例失败清理代码也会执行。

说实话这个项目没在公司落地，是自学练手的，
但整个设计过程让我理解了框架为什么要这么分层。
```

### 为什么这样讲能加分

1. **先说问题再说方案** —— 说明你是为了解决问题才这么设计，不是抄的
2. **主动说了踩过的坑** —— 说明你真跑过
3. **主动说明是自学项目** —— 诚信，而且把"没落地"转成了"但理解了设计"

### 可能追问

| 追问 | 答法要点 |
|---|---|
| "为什么用 YAML 不用 Excel？" | YAML 支持注释、层级清晰、diff 友好；Excel 适合给不懂代码的人维护，但版本管理麻烦。**两种都有人用，关键是说得出取舍** |
| "用例有多少条？" | 如实说。少不要紧，说"目前 [X] 条，主要覆盖了 XX 模块" |
| "跑一次多久？" | 如实说。 |
| "有没有接 CI？" | 如果没接："还没接，我的计划是用 Jenkins 配定时任务，拉代码跑 pytest 出报告，失败发通知" |
| "为什么没在公司用？" | "目前公司用的是 CloudTest 平台，我搭这个是想理解框架底层是怎么跑的" |

## 三、必须准备一个真实案例（最重要）

**这是你目前最大的短板。** 面试一定会问"举个例子"，答不上来前面全白讲。

从华为钱包经历里挖一个，按这个结构填：

```
【背景】当时在测 [XX 功能]，[什么场景]
【现象】出现了 [什么异常]
【排查】我通过 [查日志 / 抓包 / 对比请求] 发现 [根本原因]
【结果】确认是 [前端/后端/数据/环境] 的问题，提单后 [怎么解决的]
【补充】后来我 [加了什么用例 / 总结了什么经验]
```

### 如果你暂时想不起来，从这几个方向挖

1. **回调相关**：有没有回调失败、重复回调、回调顺序错乱的情况？
2. **签名相关**：有没有签名算错、验签失败、时间戳过期导致的失败？
3. **多区域相关**：某个区域特有的问题？环境配置搞混过？
4. **状态流转**：卡券状态（未使用/已使用/已过期）有没有流转错的？
5. **边界值**：金额、数量、有效期有没有踩过边界 bug？
6. **数据一致性**：商户侧和用户侧状态不一致的情况？

> **不要编。** 想不起来就老实说"时间有点久，具体细节我记不清了，
> 但我记得当时主要的问题集中在 XX 方面"。
> 编造的细节一追问就穿帮。

## 四、如果面试官问"你有什么优势"

```
我觉得我的优势是 [选一个，说具体]：

选项 A（有接口测试经验 + 懂业务）：
    我做过金融级业务的接口测试，对一致性、幂等、安全这些点比较敏感，
    不是只会按用例点点点。

选项 B（自学能力）：
    我之前主要用平台做测试，后来自己从头搭了一套 Python 框架，
    遇到问题会自己查资料解决。

选项 C（定位问题能力）：
    我习惯先看日志和抓包定位是前端还是后端的问题，再提单，
    这样能减少来回扯皮。
```

**选一个说透，不要三个都列**——三个都列等于没有重点。

## 五、绝对不要说的话

| 别说 | 为什么 | 改成 |
|---|---|---|
| "方法都是别人封装好的" | 等于自认工具人 | "平台管通用能力，业务编排和异常定位是我做" |
| "我只是执行用例" | 自降身价 | "我负责用例设计和问题定位" |
| "这个我没做过" | 直接结束话题 | "这个我没实际做过，我的理解是……" |
| "我精通 Python" | 一问就穿 | "能独立写自动化脚本和框架，复杂算法还不行" |
| "框架是我从零写的"（如果是参考的） | 背调/追问风险 | "参考开源项目搭的，按自己理解改了 XX" |
| "我们公司项目用了我这套框架"（如果没用） | 严重诚信问题 | "这是我自学的练手项目" |

## 六、面试前 10 分钟快速过一遍

1. 我是谁，做过什么（1 分钟版本）
2. 我的框架分几层，为什么这么分
3. 一个真实案例（背景-现象-排查-结果）
4. 一个技术难点（最好是真踩过的坑）
5. 我的不足 + 改进方向
6. 一个反问

**说不清楚的地方，就是明天要补的地方。**
