# 5 天 Python 自动化面试冲刺

> 定位：**面试冲刺**，不是系统入门。
> 每一章都会标注 `【面试考点】`——那是面试官真正会追的地方。
> 目标不是"学完所有知识"，而是 **5 天后能扛住 Python 自动化岗的面试，并且有东西可讲**。

---

## 这套课和 dsh 的区别

桌面上已有的 `dsh/api-auto-test` 是 7 天系统课，但它有个缺口：**没有 Python 语言基础**，day1 直接上 requests。
后果是你学完能照着写，但面试官问一句"fixture 为什么用 yield"，你就卡住了。

所以这套课的排法不同：

| | dsh（7天） | AA（5天） |
|---|---|---|
| 起点 | requests | Python 三座大山（装饰器/yield/类） |
| 目标 | 能搭框架 | 能搭框架 **且能讲清楚为什么这么搭** |
| 收尾 | CI 集成 | CI + 面试包装、项目话术、追问预案 |

## 学习方法（重要，别跳）

1. **代码必须手敲**，不要复制粘贴。手敲过和看过是两回事，面试时肌肉记忆只有手敲才有。
2. **先跑通再理解**。每个 `code/` 下的脚本先运行一遍看输出，再回头读教程。
3. **遇到报错别急着问**：先看最后一行错误信息，80% 的问题在那里写着。
4. **Day 1 和 Day 4 是重点**，如果时间不够，Day 3 可以压缩，Day 1 和 Day 4 不能省。
5. 每天结束时，合上文档，**用自己的话复述一遍今天学了什么**。说不出来就是没掌握。

## 这份材料是按"不许假绿"写的

本项目的主题是测试，所以框架里特意**堵掉了四类"看起来通过了其实没验证"的情况**：

| 假绿路径 | 框架的反应 |
|---|---|
| 用例漏写 `validate` / 拼成 `validates` | 报错，不判通过 |
| JSONPath 路径写错（`is_null` 恰好"通过"、`ne` 恒真通过） | 报错「路径未匹配」，与「值为 null」严格区分 |
| `extract` 提不到值 | 报错，而不是打条 WARNING 继续跑 |
| 服务端返回 500 + HTML | 干净的断言失败，不是把 `JSONDecodeError` 甩给你 |

`unit/test_common.py` 里每一条都配了回归测试——**改动框架时如果把这些兜底删了，
`pytest unit/` 会立刻变红**。具体说明在 Day 4 教程第四节。

## 已知限制

写在这里，免得你踩了以为是自己的问题。

| 限制 | 说明 |
|---|---|
| **Day 4 框架默认跑不了 `-n` 并发** | 框架靠全局变量池在用例间传接口依赖，而 `pytest-xdist` 是多进程、内存不共享。传 `-n` 会被框架**忽略并降级为串行**，开头和结尾各提示一次，**退出码仍是 0**——所以 CI 上会"绿着但没并发"。想让它在 CI 里直接失败，加 `--strict-parallel`。完整分析在 Day 4 教程「为什么 `-n` 并发用不了」 |
| Day 4 的用例**不独立** | 用例间有顺序依赖，所以单条执行、`-k` 筛选、`--lf`、失败重试都会踩到"前置没跑"。另外**写操作不能盲目重试**（重试一条支付用例 = 可能重复支付） |
| Day 3 的用例可以并发 | `pytest -n 4` 能跑通（49 passed）—— 因为它没有跨用例的数据依赖。这个对比本身就值得体会 |
| mock 服务数据在内存里 | 重启服务就重置，不持久化；课程里没有真实数据库，Day2 的库表校验课只演示套路 |
| Day 5 的 CI / Allure 是**未落地**的 | 仓库里没有 CI 配置，`requirements.txt` 也没装 `allure-pytest`。这部分按"能说清概念和写法"来准备，不要讲成"已经做了" |
