# 一、装饰器

## 1.1 先理解一件事：函数在 Python 里是"东西"

这一点没搞清，装饰器永远学不会。

```python
def hello():
    print("你好")

# 函数可以被赋值给变量
a = hello      # 注意：没有括号
a()            # 输出：你好

# 函数可以作为参数传给另一个函数
def run(func):
    func()

run(hello)     # 输出：你好
```

**关键点**：
- `hello` 是函数本身（一个"东西"）
- `hello()` 是调用它、拿返回值

括号的有无，是初学者最大的困惑来源。记住：**不带括号是"东西"，带括号是"执行"**。

## 1.2 闭包：函数里面再定义函数，并返回它

```python
def outer():
    msg = "我是外层变量"
    def inner():
        print(msg)          # 内层函数用了外层的变量
    return inner            # 返回内层函数（不带括号！）

f = outer()
f()                         # 输出：我是外层变量
```

`f = outer()` 之后，`outer` 已经执行完了，但 `msg` 还被 `inner` 记着。
这种"内层函数记住了外层变量"的现象叫**闭包**。

> 术语解释：**闭包**（closure）= 函数 + 它引用的外部变量，打包在一起。

## 1.3 装饰器干什么用？

需求：有几个函数，我想给它们**都加上"打印开始/结束日志"的功能**，但不能改函数内部的代码。

最笨的办法是每个函数里都加两行 print——10 个函数就加 20 行，重复且难维护。

装饰器就是解决这个的：**不改原函数，给它套一层额外功能。**

先不用 `@` 语法，用最朴素的方式写一遍，你就懂了：

```python
def login():
    print("执行登录逻辑")

# 写一个"包装工"
def log_wrapper(func):          # func 就是被包装的函数（login）
    def inner():
        print("=== 开始执行 ===")
        func()                  # 执行真正的 login
        print("=== 执行结束 ===")
    return inner                # 返回包装后的新函数

# 手动包装
login = log_wrapper(login)      # login 现在是被包装过的版本
login()
```

输出：
```
=== 开始执行 ===
执行登录逻辑
=== 执行结束 ===
```

看明白了吗？**`log_wrapper(login)` 返回了一个"加了日志功能的 login"**，然后我们把它赋回给 `login` 这个名字。

## 1.4 `@` 就是上面那句的语法糖

```python
def log_wrapper(func):
    def inner():
        print("=== 开始执行 ===")
        func()
        print("=== 执行结束 ===")
    return inner

@log_wrapper                    # 等价于：login = log_wrapper(login)
def login():
    print("执行登录逻辑")

login()
```

**`@log_wrapper` 就等价于 `login = log_wrapper(login)`**，只是写在了函数定义的上方。

这就是装饰器。没有魔法。

## 1.5 被装饰的函数有参数怎么办？

用 `*args` 和 `**kwargs` 接住所有参数，再原样传给原函数。

```python
def log_wrapper(func):
    def inner(*args, **kwargs):        # 接住所有参数
        print(f"=== 开始执行 {func.__name__} ===")
        result = func(*args, **kwargs)  # 原样传下去
        print("=== 执行结束 ===")
        return result                   # 记得把返回值还回去！
    return inner

@log_wrapper
def add(a, b):
    return a + b

print(add(1, 2))
```

输出：
```
=== 开始执行 add ===
=== 执行结束 ===
3
```

> 术语解释：
> - `*args`：接收任意多个**位置参数**，打包成元组
> - `**kwargs`：接收任意多个**关键字参数**，打包成字典
> - `func(*args, **kwargs)`：把元组和字典**拆开**再传进去（这叫解包）

**两个必犯的错**：
1. `inner` 忘了写 `*args, **kwargs` → 原函数有参数时报错
2. 忘了 `return result` → 原函数的返回值被吞掉，变成 `None`

## 1.6 `functools.wraps` 为什么必须加

```python
import functools

def log_wrapper(func):
    @functools.wraps(func)          # ← 加这一行
    def inner(*args, **kwargs):
        ...
    return inner
```

不加会怎样：被装饰后的函数，`__name__` 会变成 `inner` 而不是原来的名字。

```python
@log_wrapper
def login(): ...

print(login.__name__)
# 不加 wraps → inner
# 加了 wraps → login
```

影响：
- 日志里打印的函数名全变成 `inner`，排查问题时看不出是哪个函数
- pytest 收集用例时可能出问题

**结论：写装饰器就加 `@functools.wraps(func)`，养成习惯。**

## 1.7 实战：写一个计时的装饰器

```python
import time
import functools

def timer(func):
    """统计函数运行时间"""
    @functools.wraps(func)
    def inner(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        cost = time.time() - start
        print(f"[{func.__name__}] 耗时 {cost:.3f} 秒")
        return result
    return inner

@timer
def slow_task():
    time.sleep(1)

slow_task()   # 输出：[slow_task] 耗时 1.00x 秒
```

## 1.8 带参数的装饰器（进阶，面试加分）

想让装饰器自己能接收参数，比如 `@retry(times=3)`：

```python
def retry(times=3):
    """外层接收装饰器自己的参数"""
    def decorator(func):            # 中层接收被装饰的函数
        @functools.wraps(func)
        def inner(*args, **kwargs):  # 内层才是真正的执行体
            for i in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"第 {i+1} 次失败：{e}")
                    if i == times - 1:
                        raise
        return inner
    return decorator

@retry(times=3)
def unstable_api():
    import random
    if random.random() < 0.7:
        raise ConnectionError("网络抖动")
    return "成功"

unstable_api()
```

三层：`retry(times=3)`  →  返回 `decorator`  →  `decorator(func)`  →  返回 `inner`。

理解不了就先记住这个套路，用多了自然懂。**面试时能写两层就够了，能写三层是加分。**

# 二、yield

## 2.1 return vs yield：一句话区别

- `return`：返回值，**然后函数结束**，下次调用从头开始
- `yield`：返回（产出）值，**函数在这里"暂停"**，下次从这里继续

## 2.2 看个例子就懂了

```python
def with_return():
    return 1
    return 2          # 永远执行不到

def with_yield():
    yield 1
    yield 2
    yield 3

print(with_return())      # 1
print(with_yield())       # <generator object ...>   ← 注意！不是 1
```

`yield` 的函数被调用时，**函数体一行都不执行**，直接返回一个**生成器对象**。

> 术语解释：**生成器**（generator）= 一个能"逐个产出值"的对象，你取一个它给一个。

```python
g = with_yield()
print(next(g))   # 1
print(next(g))   # 2
print(next(g))   # 3
print(next(g))   # StopIteration 报错，因为没有更多了
```

用 `for` 循环更常见：

```python
for x in with_yield():
    print(x)
# 1
# 2
# 3
```

## 2.3 为什么需要生成器？省内存

需求：生成一个包含 1000 万个数字的列表。

```python
# 用列表：1000 万个数字全在内存里
def make_list(n):
    result = []
    for i in range(n):
        result.append(i)
    return result

# 用生成器：一次只在内存里放一个
def make_gen(n):
    for i in range(n):
        yield i
```

列表版本会吃掉几百 MB 内存；生成器版本几乎不占内存，因为它是**用的时候才生成**。

这叫**惰性求值**（lazy evaluation）—— 需要才算，不要不算。

> 类比：列表是"把整本书印好给你"，生成器是"你翻一页我印一页"。

## 2.4 重点：yield 做前后置（pytest 的核心用法）

这是你**必须理解**的地方，因为 pytest 的前后置完全靠它。

```python
def db_connection():
    print("1. 连接数据库")        # setup：yield 之前
    conn = "我是数据库连接"
    yield conn                    # 把连接交给外面用，然后暂停
    print("3. 关闭数据库连接")     # teardown：yield 之后
```

用它：

```python
gen = db_connection()
conn = next(gen)          # 执行到 yield，拿到 conn，暂停
print(f"2. 用 {conn} 查询数据")
try:
    next(gen)             # 继续执行 yield 之后的代码
except StopIteration:
    pass                  # 生成器正常结束
```

输出：
```
1. 连接数据库
2. 用 我是数据库连接 查询数据
3. 关闭数据库连接
```

**看懂了吗？yield 把一个函数从中间劈成了两半**：
- 前半段是"准备资源"
- 后半段是"清理资源"

pytest 的 fixture 就是这么干的：

```python
@pytest.fixture
def login():
    token = do_login()      # yield 前：登录（setup）
    yield token             # 把 token 给用例
    do_logout()             # yield 后：退出（teardown）
```

**这就是"yield 为什么是 pytest 的灵魂"。**

## 2.5 更优雅的写法：contextmanager

不用手动 `next()`，用 `with` 语句：

```python
from contextlib import contextmanager

@contextmanager
def db_connection():
    print("1. 连接数据库")
    yield "我是数据库连接"
    print("3. 关闭数据库连接")

with db_connection() as conn:
    print(f"2. 用 {conn} 查询数据")
```

`with` 块结束时，会自动执行 yield 之后的代码（即使中间出异常也会执行）。

> 这叫**上下文管理器**，`with open(...) as f` 就是同一个东西，文件会自动关闭。

## 【面试考点】yield

**Q1：yield 和 return 的区别？**

> `return` 返回值后函数立即结束，下次调用从头执行，所有值一次性在内存里。
> `yield` 返回值后函数**在原地暂停**，下次调用从暂停处继续，值是一个个产出的，几乎不占内存。
> 含 yield 的函数调用后返回的是生成器对象，函数体不会立即执行。

**Q2：pytest 的 fixture 为什么用 yield 而不是 return？**

> 因为需要"前后置"：yield 之前是 setup（准备数据/登录），yield 之后是 teardown（清理数据/退出登录）。
> 用 return 的话函数直接结束，清理代码执行不到。
> pytest 在用例结束后会自动触发生成器继续走完 yield 之后的部分。

**Q3：生成器有什么好处？**

> 惰性求值，按需生成，节省内存。处理大文件、大数据集时不会一次性加载到内存。
> 典型场景：逐行读取大日志文件。

**Q4：怎么读取一个大文件（比如 10G 的日志）？**（进阶，很常见的题）

```python
def read_large_file(path):
    with open(path, encoding="utf-8") as f:
        for line in f:          # 文件对象本身就是迭代器，一次只取一行
            yield line

for line in read_large_file("huge.log"):
    if "ERROR" in line:
        print(line)
```

> 要点：不能 `f.read()`（一次性读进内存会爆），要 `for line in f` 逐行迭代。

# 三、面向对象（类）

## 3.1 为什么需要类？

先体会"不用类有多痛"。假设要管理多个用户的接口：

```python
user1_name = "admin"
user1_phone = "138..."
user1_token = "xxx"

user2_name = "tester"
user2_phone = "139..."
user2_token = "yyy"
```

10 个用户就是 30 个变量，改一个字段名要改 10 处。

用类：

```python
class User:
    def __init__(self, name, phone):
        self.name = name
        self.phone = phone

u1 = User("admin", "138...")
u2 = User("tester", "139...")
print(u1.name)      # admin
```

**类 = 图纸，实例 = 按图纸造出来的东西。**

- `class User` 是图纸（模板）
- `u1 = User(...)` 是按图纸造出来的一个具体用户
- 造 100 个用户也不用多写一行代码

## 3.2 `__init__` 和 `self` 到底是什么

```python
class User:
    def __init__(self, name, phone):
        self.name = name      # 把参数存到实例上
        self.phone = phone
```

- `__init__`：构造方法，**创建对象时自动调用**，用来初始化属性
- `self`：指代**当前这个实例本身**。`u1.name` 里的 `u1` 就是 `self`

```python
u1 = User("admin", "138")
# 实际发生的是：User.__init__(u1, "admin", "138")
# 所以 self 就是 u1
```

> 术语解释：`self` 不是关键字，只是约定俗成的名字，换成别的也能跑，但**千万别换**，所有 Python 程序员都认这个。

## 3.3 类属性 vs 实例属性（经典坑）

```python
class Config:
    env = "test"              # 类属性：所有实例共享

    def __init__(self, name):
        self.name = name      # 实例属性：每个实例各有各的

a = Config("A")
b = Config("B")

print(a.name, b.name)   # A B      ← 各是各的
print(a.env, b.env)     # test test

Config.env = "prod"     # 改类属性
print(a.env, b.env)     # prod prod  ← 全都变了！
```

**记住**：
- 定义在 `class` 里、`__init__` 外的 → 类属性，所有实例共享
- 定义在 `__init__` 里、`self.xxx` 的 → 实例属性，各管各的

这个坑在框架里很常见：把 `base_url` 定义成类属性，改一处全局生效，这是**故意的**用法。

## 3.4 方法

```python
class UserAPI:
    def __init__(self):
        self.token = None

    def login(self, username, password):     # 第一个参数必须是 self
        self.token = "mock_token"
        return self.token

    def get_user(self, uid):
        print(f"用 {self.token} 查询用户 {uid}")

api = UserAPI()
api.login("admin", "123456")
api.get_user(1)
```

`self.token` 在 `login` 里存进去，`get_user` 里还能用——**这就是类最大的价值：方法之间可以共享状态**。

不用类的话，你得把 token 传来传去，或者用全局变量（很脏）。

## 3.5 继承：把公共代码抽到父类

这是**框架分层的核心**。

场景：登录接口、用户接口、订单接口，都要发请求、都要记日志。
难道每个都写一遍 `requests.post` 吗？

```python
class BaseAPI:
    """父类：只放公共能力"""
    def __init__(self):
        self.base_url = "http://127.0.0.1:5000"
        self.session = requests.Session()

    def request(self, method, path, **kwargs):
        url = self.base_url + path
        print(f"请求：{method} {url}")
        resp = self.session.request(method, url, **kwargs)
        print(f"响应：{resp.status_code}")
        return resp


class UserAPI(BaseAPI):
    """子类：只写业务"""
    def login(self, username, password):
        return self.request("POST", "/api/login",
                            json={"username": username, "password": password})

    def get_user(self, uid):
        return self.request("GET", f"/api/user/{uid}")


class OrderAPI(BaseAPI):
    def create_order(self, user_id, amount):
        return self.request("POST", "/api/order",
                            json={"userId": user_id, "amount": amount})
```

**好处**：
- 请求逻辑、日志只在父类写一次
- 要加"统一超时"或"统一重试"，只改父类一处
- 子类只关心业务参数

这就是 Day 4 要做的分层。**现在看不懂没关系，记住"公共的放父类，业务的放子类"这句话。**

## 3.6 `super()` 是干嘛的

子类重写父类方法时，想先执行父类的，再加点自己的：

```python
class BaseAPI:
    def __init__(self):
        self.base_url = "http://127.0.0.1:5000"

class UserAPI(BaseAPI):
    def __init__(self):
        super().__init__()          # 先调用父类的 __init__
        self.token = None           # 再加自己的属性

api = UserAPI()
print(api.base_url)    # 继承自父类
print(api.token)       # 自己的
```

> 术语解释：**重写**（override）= 子类定义了和父类同名的方法，覆盖父类的版本。
> `super()` = 拿到父类的引用，调用父类的方法。

## 3.7 `__str__` 和 `__repr__`（加分项）

这类前后带双下划线的叫**魔术方法**（magic method），在特定时机自动触发。

```python
class User:
    def __init__(self, name):
        self.name = name
    def __str__(self):
        return f"用户({self.name})"

u = User("admin")
print(u)        # 用户(admin)   ← 自动调用 __str__
```

不加 `__str__` 的话，`print(u)` 会输出 `<__main__.User object at 0x...>`，调试时看不出是谁。

常见的魔术方法：
- `__init__`：创建对象时
- `__str__`：print 时
- `__len__`：`len(obj)` 时
- `__call__`：`obj()` 时（把实例当函数调用）

## 【面试考点】面向对象

**Q1：`__init__` 和 `__new__` 的区别？**

> `__new__` 负责**创建对象**（分配内存），是真正的构造方法，第一个参数是 `cls`（类本身）。
> `__init__` 负责**初始化对象**（给属性赋值），第一个参数是 `self`。
> 执行顺序：`__new__` 先，`__init__` 后。
> 一般业务代码只写 `__init__`，`__new__` 用在单例模式等场景。

**Q2：类属性和实例属性的区别？**

> 类属性定义在类里、方法外，所有实例**共享同一份**，通过类名或实例都能访问，改一处全局生效。
> 实例属性定义在 `__init__` 里用 `self.xxx`，每个实例**独立一份**。
> 坑：如果通过实例给类属性赋值（`a.env = "x"`），实际是给 a 新建了一个实例属性，不会影响其他实例。

**Q3：你框架里怎么用继承的？**

> 抽一个 `BaseAPI` 父类，封装 requests 请求、日志记录、异常处理、超时重试这些公共能力。
> 各个业务类（UserAPI / OrderAPI）继承它，只写接口路径和业务参数。
> 这样公共逻辑只有一份，要加统一处理（比如统一加请求头、统一重试）只改父类。

**Q4：什么是封装？**

> 把数据和操作数据的方法打包到类里，对外只暴露必要的接口，内部实现细节隐藏起来。
> 好处：调用方不用关心内部怎么实现，内部改了不影响外部调用。
> Python 里用单下划线 `_xxx` 表示"约定上私有"，双下划线 `__xxx` 会做名称改写（name mangling）。

## 4.1 文件读写：JSON 和 YAML

测试用例数据不能写死在代码里，要放到文件里。这就是**数据驱动**的基础。

**JSON**：

```python
import json

# 写
data = {"name": "admin", "pwd": "123456"}
with open("user.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

# 读
with open("user.json", "r", encoding="utf-8") as f:
    data = json.load(f)
```

> `ensure_ascii=False`：不加的话中文会被写成 `\u4e2d\u6587`。
> `with open(...)`：用完自动关闭文件，不用手动 `f.close()`。

**YAML**（自动化框架更常用，因为能写注释）：

```python
import yaml

case = """
name: 登录成功
request:
  method: POST
  url: /api/login
  json:
    username: admin
    password: "123456"
validate:
  - eq: [$.code, 0]
"""

data = yaml.safe_load(case)
print(data["request"]["method"])   # POST
```

> 术语解释：**YAML** 是一种配置文件格式，用缩进表示层级，比 JSON 更适合人写。
> 注意缩进必须用空格，不能用 Tab。

## 4.2 异常处理

```python
try:
    resp = requests.get(url, timeout=5)
    resp.raise_for_status()          # 4xx/5xx 会抛异常
except requests.exceptions.Timeout:
    print("请求超时了")
except requests.exceptions.RequestException as e:
    print(f"请求失败：{e}")
else:
    print("没出异常才会走这里")
finally:
    print("无论是否异常都会走这里，通常用来关闭资源")
```

要点：
- 捕获异常要**从具体到宽泛**，`Timeout` 写在 `RequestException` 前面（它是子类）
- `else`：没异常时执行
- `finally`：一定执行，用来关连接、关文件
- `raise`：主动抛出异常

框架里为什么要异常处理？**一个用例的接口挂了，不应该让整个测试跑崩**，要捕获、记日志、标记失败，继续跑下一个。
